PHP is Dead

aaronwatts@dev 3 August 2026

PHP is dead, long live PHP! I've just finished rebuilding my CMS come static site generator in PHP to replace the old Python one. I'm only just getting started on my PHP journey. As first projects go, I'm pretty pleased with this one. And it even seems to be working so far!

It wasn't too painful, and didn't take too long when considering how little free time I get to spend coding nowadays. I managed to fix a bug in my RSS feed, and while I was setting up the templates I even made some changes along the way - not the way you would want to work professionally, but I make no secret of the fact that I'm not a professional. I finished the project and dumped the whole thing into a new git repository, so you might not even be able to tell that I can't focus on any one thing at a time.

PHP is great, I think. I never felt particularly stuck, every problem was easily solved using the docs or the W3 site. There's a few things I will have to change slightly to improve it's shelf life, and to incorporate this blog into the main site. This will likely be the last post I do using Publii. I just need to throw together a web scraper, which I'm eyeing up php-curl for that project, and scrape these blog entries into HTML files for my main site to use.

I thought a change to how Python handles strings was stopping my pre strings not to preserve line breaks in the RSS feeds, but the issue seems to be with the XML itself. I have no idea why it was working before, and suddenly stopped. I tried various methods of escaping entities and formatting strings to try and prevent it. But since I'm using PHP, I thought I would just use a CDATA enclosure around the string. That fixed it. I did try to use CDATA with Python, but I couldn't find a XML parser in Python that got on with it. PHP it was pretty easy just to enclose the string in CDATA tags using concatenation. So that's solved now.

While I was working through the various templates, I decided to make my topic tags more distinct from the topic filter buttons used in the filter search on the blog roll pages. I also swapped out my RSS svg for one from the new Material icons. I looked at a few icon providers, and Material seemed to offer the cleanest SVG code blocks without dependencies. I also nabbed a copy-content SVG and added copy link buttons to my RSS feed links. Like my filter search, I've set it up to default to display: none; unless JavaScript is detected, since it requires JavaScript to work. Neither of the SVG's are accessibility friendly yet, but I will add some screen reader text sometime soon.
