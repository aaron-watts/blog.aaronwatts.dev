An Amateurs Take on NextCloud

aaronwatts@dev 5 June 2026

I've been using NextCloud on a VPS running Ubuntu for perhaps a year now. I didn't have any server experience prior to setting it up. It was a little scary at first, but it's been a learning journey that, overall, I think I've enjoyed so far.

I am by no means an expert yet. But I have conquered the inertia that is caused by the thought: "it might be too difficult for me". Since setting it up I have also gained the courage to convert an old Raspberry Pi into a Coolify server at home.

At this point it is worth noting that I've already written a piece about NextCloud, but that was just a short tech review, and while I may repeat some points here, I intend to look a little deeper at my experience of setting up and running my own NextCloud instance over the past year.

Setting up the NextCloud server in the first place was the hardest bit. Things may have changed since when I first used it, but Hostinger's All-In-One NextCloud image installs either a Docker or a Snap image - I can't actually remember which one anymore. But I do remember that it meant the NextCloud documentation didn't exactly line up well with user experience - as it assumes you are working with a LAMP installation. As a first-timer, I couldn't figure out how to set up the DNS. Having learned a little more about running Linux servers, it might be interesting to see if I could figure that out now or not after a little levelling up - but currently there's no real need, everything is working - if it's not broken, don't fix it. In the end the easy option, while it sets you up with a fully working NextCloud server within a few minutes, turned out not to be the easiest when it came time to configure DNS, adjust the config.php file and run occ tasks.

I had previously subscribed to a NextCloud provider. The providers get to choose what apps are installed on their respective instances. So switching to self hosted, I got total control over what apps I had running on my instance. My VPS is only 1 vCPU core, so while OnlyOffice ran, I couldn't quite get the sync right between server and local files - which appears to be a known bug. NextCloud Office, based on Collabora requires a second vCPU to run well, so I didn't really bother with that one after immediately encountering considerable lag. An online office suite has become less important to me since my employer has developed some kind of fetish of using check boxes in Word Documents, which work in LibreOffice and not in OnlyOffice one day, then in OnlyOffice but not LibreOffice another day. Eventually I got fed up with switching editors and just began using my employers OneDrive and Word suites in a Chromium browser for anything to do with work, and I use locally installed LibreOffice synced to my NextCloud for anything personal.

Other apps I've used include Recipe's and News, both of which sync directly into the SQL database instead of a directory. This requires Redis to be installed and configured, and a Cron job instead of AJAX. I had issues with a major update recently and couldn't see much evidence of other users having similar issues. I'm still learning how to read Logs, but it appeared to be failing at the back up phase, and I think either the apps or my redis config may have been causing the issue here.

Thankfully, NextCloud's desktop client creates synchronised local backups on whatever device you have it installed on, so when I couldn't solve the issue, I simply logged out of my instance on my local devices, made a copy of the NextCloud folder, and installed the new NextCloud version onto a clean Ubuntu install on my VPS server. Going over the process a second time was a cinch. In case the apps had caused the issue, I decided I could live without them - reinstalling would be no bother, but it's fine, I'll get by. I noticed that the new version came with Redis set up by default, so it could have well been a clash there that was preventing the update from installing, although I think I would have seen other people complaining as my assumption is that most self hosters are likely to be using Redis.

After reinstalling, I also left AJAX as the default for background tasks, as I'm only one user and I stopped using the news app so nothing really needs to sync on a schedule. But it's rare that I log in to my cloud in a browser - which is when AJAX jobs are called (one per page load). My server ended up with a pretty long queue of tasks, so I just set up the Cron job. It's as easy as just editing one file via SSH, restart the Apache2 daemon and NextCloud will detect the change and switch from AJAX to Cron automatically.

I have been keeping my Publii CMS data folder and my Calibre eBook library on my NextCloud, with no issues for either. I have to remember to install my Publii Plugins on new installs, but it's great to have all my stuff in the cloud and also locally on my devices too. I also keep my git projects on there too - not how you might be thinking though. I have my local git projects in my NextCloud as you would on your local machine, so I can resume on the same branch from the same HEAD on any of my machines. Is this wise or foolish? I don't know yet. There's nothing mission critical on there anyway, it's all just my hobbies. The only issue I have experienced is that something in my Vim config keeps creating a file that uses punctuation as the filename, NextCloud (intelligently) doesn't like that and will refuse to sync until you get rid off. If I don't spot it I can log in on my other device and find that the files are not completely up to date, although I have quickly learned to check the system tray icon to make sure everything looks okay before finishing a session at my computer.

Security wise - for a beginner, just forget about it. Sure if you want to learn how to, but if you are a noob, and are concerned about security, just go with a proper provider. I'm not saying it's not possible to have a somewhat secure NextCloud instance as a beginner, but in these times of AI assisted CVE exploits, you're better off leaving it to the professionals.

It has absolutely been an enjoyable learning experience, and while at first there's a lot of new information to process, I haven't felt overwhelmed at any point. I've learned a little bit about LAMP servers along the way, and got something useful out of it. I highly recommend self hosting NextCloud it's the kind of thing that interests you - but again, if you need something done right: let someone else host it. As I mentioned, off the back off this project I have also made a Coolify server at home to experiment with. Although, I have also decided, based off this experience, that I don't think I'd want to host a Got service, as I use GitHub a lot, and I want it to work - and for all my work to be there safely in one piece.
